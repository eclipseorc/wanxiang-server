# 代码中文导读

本文按目录说明服务端代码职责，帮助从启动入口逐层阅读。关键 Go 文件也会在包说明文件（`doc.go`）和函数附近标注中文注释。

## 启动入口

- `cmd/http-server`：加载 `.env`、打开 SQLite、初始化管理员，启动管理 API 和静态管理网页。
- `cmd/websocket-server`：加载同一份 `.env` 和数据库，启动 WebSocket 转发服务及控制事件轮询器。

建议先从这两个 `main.go` 的 `run()` 函数看启动顺序，再进入下面对应的 `internal` 包。

## 内部模块

- `internal/envfile`：读取 `KEY=value` 配置；已有系统环境变量优先。
- `internal/logic`：登录、密码哈希、用户/设备创建和 WebSocket 临时票据等业务规则。
- `internal/storage/sqlite`：数据库连接、表结构与迁移、用户/设备/分组/会话等数据访问。
- `internal/transport/httpapi`：HTTP 路由、Bearer 认证和管理 API 请求处理。
- `internal/transport/websocket`：设备和管理端连接、消息转发、观看会话以及 `com` 命令协议。

## `com` 命令示例

管理页面约每 25 秒发送一次心跳：

```json
{"type":"com","command":"ping","requestId":"ping-1","data":{"sentAt":1731670000000}}
```

服务端在 `commands.go` 中按命令白名单分发，响应会保留请求编号：

```json
{"type":"com","command":"pong","requestId":"ping-1","data":{"sentAt":1731670000000}}
```

后续扩展命令时，先定义命令名和专用数据结构，再在分发 `switch` 中增加明确处理逻辑，并为正常、错误输入补测试。会改变设备或用户状态的命令还必须增加身份、权限和会话校验。

## 日志与测试

- Go 服务的运行日志输出到启动服务的控制台；浏览器端 WebSocket 心跳日志可在开发者工具 Console 中查看。
- 在仓库根目录运行 `go test ./...` 执行 Go 测试；运行 `go vet ./...` 检查常见静态问题。
