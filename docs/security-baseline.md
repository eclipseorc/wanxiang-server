# 安全基线与已知限制

本文档归档万象服务端已落地的安全基线与单节点架构的已知限制（上线/审计参考）。

## 安全基线（改动时不要回退）

- **登录失败限速**：按「IP + 用户名」1 分钟内 5 次失败锁定 5 分钟，返回 429 + `Retry-After`；成功即清零。计数表满时直接拒绝新 key，不允许静默放行。
- **连接与票据限流**：ticket 端点按 IP 限制 60 次/分钟；设备 1000 / 管理端 200 的连接数上限。
- **防账号枚举**：用户名不存在时仍执行一次等成本 bcrypt 校验（`dummyPasswordHash`），抹平登录耗时差；失败响应文本完全统一。
- **过期清理与审计**：`sessions` / `ws_tickets` 过期行在启动、登录、签发票据时节流清理；`audit_logs` 刻意不自动删除。登录、登出、创建用户/组、分组与权限变更、设备控制都写审计；登录失败不写 DB，避免攻击放大写入。
- **HTTP 安全头**：`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、CSP、`Cache-Control: no-store`（全站）；启用内置 TLS 时加 HSTS。页面含内联脚本，CSP 保留 `'unsafe-inline'`。
- **静态资源隔离**：静态服务禁止目录列表且只允许白名单扩展名（`justFiles`），即使 `WEB_DIR` 误配也不会暴露 `.env` / `go.mod` / `*.db`。
- **WebSocket 保护**：Origin 精确白名单（Origin 拒绝时先拦截，不消耗 ticket）、一次性 ticket、512KB 读上限、单连接 100 条/秒限速、设备上报内容广播前截断、读到任意业务消息刷新 `pongWait` 空闲超时、5 秒写超时。
- **TLS 与来源 IP**：`TLS_CERT` / `TLS_KEY` 必须同时设置，最低 TLS 1.2；留空则由反向代理终止 TLS。客户端 IP 取 `RemoteAddr`，不信任 `X-Forwarded-For`（除非确认部署了可信反代）。
- **错误与权限隔离**：内部错误只写服务端日志，仅 `logic.InputError` 回显客户端；`CanAccess` 使用固定 SQL，不做列名拼接。

## 已知限制 / 上线前必做

1. 默认以明文监听 `:9001` / `:9002` / `:9003` / `:9004`；生产环境需启用内置 TLS 或由反向代理终止 TLS 并设置 HSTS。
2. 登录限速与 ticket 限速为进程内内存态，多实例需共享存储与网关层总体限速。
3. ticket 通过 URL query 传递，部署反向代理时必须确认访问日志脱敏。
4. 无 Origin 头的非浏览器客户端放行（设备原生客户端依赖此行为），CSWSH 风险由一次性 ticket 缓解。
5. 设备以 `deviceId` 为唯一凭证、无独立令牌；需由 App 强随机生成并配合 IP 限速。
6. `broadcastDevice` 同步串行推送并逐个查库，高并发场景需改为每连接发送队列 + writer goroutine。
7. scrcpy 的「单设备单观看会话」状态在内存中维护，进程重启后重置。
8. `groups` 表不区分用户组/设备组，依赖管理端正确配置。
9. 管理员密码仅在账号不存在时由 `.env` 初始化，修改 `.env` 不会轮换已有密码。
10. 审计日志尚无查询接口与轮转归档策略。
11. 历史库中 `users.created_at` 可能残留 Unix 秒字符串，不影响功能。
